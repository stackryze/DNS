# Awesome Design MD

A curated index of **74 brand design systems** captured in the "design.md" format.
Source: https://github.com/VoltAgent/awesome-design-md — full, always-current content
is hosted at https://getdesign.md.

## When to use
- You want to channel a specific brand's aesthetic (e.g. "make it feel like Linear / Stripe / Vercel").
- You need concrete tokens and rules (palette, type scale, radii, spacing, motion) to avoid generic "AI slop" defaults.
- During a design review, to compare the current UI against a reference system.

## How to use
1. Pick the closest brand(s) from `design-md/` (see `BRANDS.md` for the full list).
2. The local `design-md/<brand>/DESIGN.md` files are pointers; fetch the full,
   current spec from `https://getdesign.md/<brand>/design-md` (e.g.
   `https://getdesign.md/linear.app/design-md`).
3. Extract the concrete decisions (color/typography/spacing/motion/components) and
   apply them through the project's own design tokens — do not copy trademarked
   assets or logos.

## Available brands
See `BRANDS.md`. Highlights relevant to dark, premium, product UIs:
`linear.app`, `vercel`, `stripe`, `figma`, `framer`, `coinbase`, `cursor`,
`elevenlabs`, `clickhouse`, `intercom`, `apple`.

## Guardrails
- Reference the *language* (proportions, restraint, motion feel), not the brand identity.
- Keep to the project's own palette/tokens; a brand ref informs decisions, it is not a skin.
